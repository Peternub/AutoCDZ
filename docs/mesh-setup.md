# Подключение и эксплуатация экспериментальной интеграции

## Реальный статус

Реализованы адаптер чтения списка ДЗ, шифрование сессий, одноразовая форма, мониторинг и очередь. Проверены автоматическими тестами на локальном сервере и подставных ответах API. Собственный аккаунт МЭШ, HTTPS-домен и ключ ИИ не предоставлены, поэтому чтение реальных ДЗ, ответы реального провайдера и TLS-развёртывание не проверены.

Ни один компонент не отправляет оцениваемую работу в МЭШ. Сервис отправки возвращает `disabled`. Запись в дневнике «выполнено» не становится статусом сдачи.

## Настройка закрытого теста владельца

1. Подготовьте HTTPS-домен для обратного прокси на сервере. Приложение слушает `127.0.0.1:8080` при обычном запуске. В Compose порт контейнера опубликован только на `127.0.0.1:8080` хоста.
2. Прокси должен сохранять `Host`, устанавливать `X-Forwarded-Proto: https`, ограничивать тело 16 КБ и не записывать тела запросов. Не публикуйте порт приложения напрямую в интернет. TLS завершается на прокси. Его настройка зависит от выбранного сервера.
3. Создайте ключ шифрования локально и внесите его в `.env`. Не отправляйте ключ в чат и не сохраняйте в Git:

```powershell
.\.venv\Scripts\python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

4. Заполните `.env`:

```dotenv
MESH_EXPERIMENTAL_ENABLED=true
PUBLIC_URL=https://ваш-домен
SESSION_ENCRYPTION_KEY=ваш-ключ
OPENAI_API_KEY=ключ-провайдера
OPENAI_MODEL=модель-с-поддержкой-json-schema
POLL_INTERVAL_SECONDS=1800
```

ИИ необязателен для мониторинга списка ДЗ. Без ключа или модели задачи ИИ остаются в очереди. Сейчас клиент поддерживает только OpenAI Chat Completions; другой провайдер требует отдельного адаптера. Выбор модели и возможность использования провайдера в вашей юрисдикции нужно проверить перед включением. Само наличие ключа не подтверждает правовое основание обработки данных.

5. Перезапустите один экземпляр бота. Владелец с `ADMIN_ID` нажимает «Подключить МЭШ». Остальным пользователям экспериментальная форма недоступна. Откройте ссылку из личного чата; она действует 10 минут и не работает повторно.
6. В официальной МЭШ войдите самостоятельно и пройдите требуемые подтверждения. Прототип принимает уже существующий токен собственной сессии и ID профиля ученика, а не пароль. Подтверждённого упрощённого входа mos.ru для стороннего приложения пока нет. Если параметры сессии неизвестны, не передавайте пароль боту: сначала требуется проверка интерфейса на собственном аккаунте и согласование механизма подключения.
7. В форме подтвердите согласие на чтение. Согласие на ИИ отдельно и по умолчанию выключено. Токен проверяется запросом только списка ДЗ и сохраняется зашифрованным; исходный пароль не хранится. Автоматизация после подключения выключена.
8. Выдайте зарегистрированному владельцу тестовый доступ: `/grant ВАШ_ID 7`, затем включите автоматизацию. Первая проверка выполняется фоновым процессом, последующие — не чаще заданного интервала, минимум 30 минут. При истечении подписки чтение и новые ИИ-запросы прекращаются. Уже отправленный провайдеру запрос отозвать невозможно; его результат после приостановки не публикуется как готовый.

Для отдельной проверки списка ДЗ без вывода содержимого сессии:

```powershell
.\.venv\Scripts\python -m autocdz.check_mesh
```

Команда показывает только результат и количество записей. Она не подтверждает получение вопросов или сдачу ЦДЗ.

## Хранение и восстановление

Миграция `autocdz/migrations/001_mesh.sql` применяется автоматически и идемпотентно при открытии базы. Существующие пользователи и тестовые подписки сохраняются. Перед обновлением сделайте согласованную резервную копию SQLite: остановите бот либо используйте SQLite Backup API. Копировать только файл базы при активном WAL недостаточно.

Зашифрованные токен и ID профиля хранятся отдельно от заданий. Ключ шифрования должен резервироваться отдельно от базы; при его утрате потребуется повторное подключение. Смена ключа без перешифрования не поддерживается. Базу, резервные копии и `.env` следует ограничить правами владельца сервера.

Таблицы: `mesh_connections`, `connection_tickets`, `assignments`, `questions`, `processing_jobs`, `solutions`, `submissions`, `integration_events`. У пользовательских данных есть владелец и каскадное удаление. Журнал хранит коды событий без внешних ответов, паролей и токенов. Настройте срок хранения резервных копий отдельно: удаление в рабочей базе не уничтожает прежние резервные копии автоматически.

Очередь использует транзакционное получение задачи и аренду на 120 секунд с продлением. После штатной остановки незавершённая задача возвращается сразу; после аварийного завершения — по окончании аренды. Максимум три попытки. Временные ошибки ИИ повторяются с задержкой. Дедупликация основана на владельце, ID задания и хеше содержания. Устаревшая обработка не заменяет новую версию.

Уведомления отправляются по сохранённой настройке пользователя; при недоступности Telegram ошибка журналируется, гарантированная повторная доставка уведомлений пока не реализована. Это не удаляет задания и результаты из базы.

«Отключить МЭШ» удаляет локальную сессию, задачи, решения и ссылки подключения; прекращается фоновая обработка. Отзыва токена на стороне mos.ru нет без подтверждённого метода: при необходимости завершите сессии на официальном сайте. `/delete_me` также удаляет аккаунт бота и остальные связанные записи.

## Границы обработки

Адаптер читает только список домашних заданий и не следует URL материалов. Его DTO не включает профиль, оценки, семью или сообщения. Широкие права самого токена таким ограничением кода не сужаются.

Форматы вопросов: один или несколько вариантов, краткий ответ, число, соответствие и порядок. Их валидаторы и ИИ-клиент работают с внутренней проверенной моделью. Наличие поддержки этой модели не означает наличие парсера реальных ЦДЗ. В текущем адаптере вопросы материалов всегда остаются нераспознанными; их нельзя решить автоматически, пока не получен и не проверен действительный формат.

Числовая проверка независимо выполняет только явно переданное арифметическое выражение с `+`, `-`, `*`, `/` и скобками; произвольный текст задачи математически не проверяется. Проверка структуры и уверенность модели не гарантируют правильность решения. Соответствие сейчас допускает несколько левых элементов для одного правого, если они перечислены среди допустимых вариантов.

ИИ получает только модель вопроса; секреты и распознанные контакты блокируются. Полное автоматическое удаление всех ФИО и персональных сведений из произвольного текста не гарантируется. Неизвестные материалы не передаются ИИ. Изображения и внешние вложения пока не загружаются.

Для публичного использования нужны подтверждённые условия интеграции, коммерческого применения, обработки данных несовершеннолетних и передачи данных провайдеру. Техническое чтение собственной сессии не является таким подтверждением. Автоматическая сдача остаётся отключённой до подтверждения интерфейса, разрешений и результата реальным тестом.
