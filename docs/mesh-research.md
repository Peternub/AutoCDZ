# Исследование интеграции МЭШ

Дата: 16 ноября 2026 года.

## Существующий проект

Python 3.13, aiogram 3.32, SQLite через aiosqlite. Обработчики: `autocdz/bot.py`; настройки: `autocdz/config.py`; база: `autocdz/storage.py`; запуск: `autocdz/__main__.py`. Существуют только тестовые подписки. Рабочей интеграции Tribute, ИИ и фонового планировщика нет. Ориентир тарифа из ТЗ — 349 ₽ за 30 дней; оплату нельзя считать реализованной.

## Подтверждённые источники

- [Инструкция МЭШ на mos.ru](https://www.mos.ru/upload/documents/files/8789/Poshagovaya_instrykciya.pdf): обычный вход связан с учётной записью mos.ru. Это не документация OAuth для стороннего приложения.
- [Документация SchoolMosPy](https://xd2dd.github.io/schoolmospy/api/student_client/): клиент принимает существующий токен и идентификатор профиля.
- [Исходник клиента домашних заданий](https://github.com/xd2dd/schoolmospy/blob/215e96720af733d5a454da27f1c9c827e3ab8b8e/schoolmospy/core/homeworks_client.py): GET `https://school.mos.ru/api/family/web/v1/homeworks`, параметры `from`, `to`, `student_id`.
- [Исходник общих заголовков](https://github.com/xd2dd/schoolmospy/blob/215e96720af733d5a454da27f1c9c827e3ab8b8e/schoolmospy/core/basic_client.py): `Authorization: Bearer …`, `Profile-Id`, `Profile-Type: student`, `X-mes-subsystem: familyweb`.
- [Модель домашнего задания](https://github.com/xd2dd/schoolmospy/blob/215e96720af733d5a454da27f1c9c827e3ab8b8e/schoolmospy/models/homeworks.py): описание, даты, предмет, идентификаторы, материалы. Структуры вопросов и подтверждения оцениваемой сдачи здесь нет.

Исходники изучены на коммите `215e96720af733d5a454da27f1c9c827e3ab8b8e`. Документация клиента местами расходится с его моделями, поэтому адаптер должен проверять ответы и останавливаться при неизвестной структуре. Код сторонней GPL-библиотеки не включается в проект; сетевой адаптер реализуется отдельно по проверенному интерфейсу.

## Механизм прототипа

Только экспериментальное чтение собственного аккаунта владельца по уже существующей сессии, передаваемой через HTTPS-форму. Пароль не запрашивается и не хранится. Ссылка подключения выдаётся владельцу в личном чате, действует ограниченное время и используется однократно. Токен хранится зашифрованным отдельным ключом вне базы. После 401/403 сессия удаляется, требуется повторное подключение. Автоматическое обновление сессии без документированного механизма не реализуется.

Этот механизм не является подтверждённой партнёрской интеграцией или упрощённым входом по логину и паролю. Он отключён по умолчанию. HTTPS-домен и собственная сессия для проверки не предоставлены. Вход через mos.ru, CAPTCHA и подтверждения пользователь проходит только на официальном сайте. Токен не следует присылать в Telegram.

## Ограничения доступа и обработки

Токен может давать широкие права, включая доступ к другим разделам аккаунта. Ограничение запросов нашего адаптера одним методом чтения не ограничивает права самого токена. Компонент не запрашивает профиль, оценки, семью, питание или сообщения и не следует ссылкам материалов. Чужие URL и перенаправления не используются.

Ответ со списком домашних заданий не доказывает наличие полного содержания ЦДЗ. Нераспознанные цифровые материалы должны получать статус «Неподдерживаемый формат»; придумывать вопросы по названию или описанию нельзя. Поле `is_done` и метод `homeworks.done()` — отметка в дневнике, а не подтверждение сдачи оцениваемого теста. Автосдача остаётся выключенной.

ИИ получает отдельную строгую модель вопроса без профиля и сессии. Дополнительно блокируются распознанные секреты и контактные данные. Автоматический фильтр не гарантирует распознавание всех ФИО и личных сведений в свободном тексте; обработка разрешается только после отдельного согласия, а непроверенные материалы не пересылаются ИИ автоматически.

## Что требуется для реальной проверки

1. HTTPS-домен с TLS и собственный тестовый аккаунт. Секреты вводятся локально, не в переписке и не в Git.
2. Проверка чтения заданий на этом аккаунте и обезличенные примеры действительных форматов вопросов ЦДЗ.
3. Выбранный ИИ-провайдер и ключ в окружении сервера.
4. Условия доступа к МЭШ, коммерческого использования, обработки данных несовершеннолетних и передачи учебных материалов провайдеру должны быть подтверждены владельцем. Правомерность автоматической отправки пока не подтверждена.

Работающий запрос к собственному аккаунту сам по себе не подтверждает допустимость публичного коммерческого сервиса. До проверки реального аккаунта получение ЦДЗ и сдача не считаются проверенными.
